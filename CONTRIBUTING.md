# Contributing to EduLedger

Thank you for your interest in contributing to EduLedger! We welcome developers, designers, testers, and documentation contributors who want to help improve the project.

## Getting Started

1. Fork the EduLedger repository on GitHub.
2. Clone your fork to your computer.
3. Follow the installation instructions in `README.md`.
4. Create a new branch for your work.

## Creating a Branch

Use a descriptive branch name that explains your contribution.

Examples:

- `feat/student-registration`
- `fix/school-form-validation`
- `docs/update-installation-guide`

## Making Changes

- Keep changes focused on one task whenever possible.
- Write clear, descriptive commit messages.
- Follow the existing code style.
- Test your changes before submitting them.
- Do not commit passwords, API keys, environment secrets, or local database files.

## Submitting a Pull Request

1. Push your branch to your fork.
2. Open a pull request against the `main` branch of EduLedger.
3. Explain what you changed and why.
4. Include screenshots when your changes affect the user interface.
5. Mention any related issues.

Please be patient while maintainers review your contribution. Changes may require discussion or revision before merging.

## Reporting Bugs

When reporting a bug, include:

- A clear description of the problem.
- Steps to reproduce it.
- What you expected to happen.
- What actually happened.
- Relevant error messages or screenshots.

Never include passwords, private information, or real student records in bug reports.

## Suggesting Features

Feature suggestions are welcome. Explain the problem the feature would solve, how you expect it to work, and any alternatives you have considered.

## Code of Conduct

Treat other contributors with respect. Be constructive when reviewing code, welcoming toward newcomers, and professional when resolving disagreements.
